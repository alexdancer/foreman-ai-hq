# Specification workflow migration ledger

## Purpose

This ledger is the reviewer-visible proof that the former distributed specification workflow was transferred before its files were removed. It names every former capability and change, identifies its destination, and records intentional supersession. Historical Git history remains provenance; no retired archive is retained in the working tree.

## Pre-removal inventory

- Former canonical capability documents: **51**.
- Former active design change: **9 files** (`proposal`, `design`, `tasks`, and six capability deltas).
- Former archived changes: **100 directories**.
- Former tracked workflow files/configuration/instructions: **45** integration files plus the capability tree.
- Claude Design source assets retained: `DESIGN.md` and `docs/design/portal-operator-workbench.md`; the design-tool ZIP artifacts were never tracked and are not recreated.

## Destination rules

- Current behavior and all surviving requirements from canonical capability documents live in `docs/specs/product-spec.md` under the matching capability heading.
- Technical boundaries, accepted consistency decisions, and non-negotiable contracts live in `docs/specs/technical-spec.md`.
- Scenario-level verification and the accepted Portal interaction matrix live in `docs/specs/test-contract.md`.
- The active Portal task breakdown lives in `docs/specs/implementation-tasks.md` using the official tracer-bullet ticket shape.
- Domain vocabulary remains in `CONTEXT.md`; hard-to-reverse decisions remain in `docs/adr/`.
